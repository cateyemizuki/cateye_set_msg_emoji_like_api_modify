# 表情映射扩展配置指南

> 如何为插件扩展/覆盖 QQ 表情 ID → 名称映射，让表情回应通知显示正确表情名。
> 无需改代码，只需编辑 JSON 文件（或环境变量指向的 JSON）。

---

## 1. 映射文件加载顺序（后加载覆盖先加载）

| 优先级 | 文件 | 说明 |
|--------|------|------|
| 1（最底） | `emoji_map/qq_face_merged.json` | 内置合并映射（265 条：经典 face + Unicode），随插件分发 |
| 2 | `emoji_map/emoji_reaction_extra.json` | 内置扩展表（表情回应专用 ID：12951/379=点赞） |
| 3 | 环境变量 `QQ_EMOJI_EXTRA` 指向的 JSON | 全局扩展（可选） |
| 4（最顶） | `QQEmojiResolver(extra_paths=[...])` 传入的路径 | 代码级扩展（可选） |

> **同一个 ID 出现在多个文件中时，后加载的覆盖先加载的。**

---

## 2. 三种 JSON 格式（任选其一）

### 格式 A：简单字典（推荐，最简单）

`id` → `名称` 的映射：

```json
{
  "12951": "点赞",
  "379": "点赞",
  "999001": "牛逼",
  "999002": "666"
}
```

### 格式 B：emojis 列表（带别名，可读性更好）

```json
{
  "emojis": [
    { "id": 12951, "name": "点赞", "aliases": ["大赞", "点赞表情"] },
    { "id": 379, "name": "点赞", "aliases": ["赞", "👍"] }
  ]
}
```

### 格式 C：纯列表

```json
[
  { "id": 12951, "name": "点赞" },
  { "id": 999001, "name": "牛逼" }
]
```

> 注意：本项目的解析器主要读 **id → 名称**（格式 A 或 B/C 的 id+name 字段）。
> 别名（aliases）目前保留给反向查询（名称 → id，如 `/el debug s` 用别名指定表情）扩展用。

---

## 3. 推荐配置位置

### 3.1 插件内扩展（推荐，随插件分发）

编辑 `emoji_map/emoji_reaction_extra.json`：

```json
{
  "12951": "点赞",
  "379": "点赞",
  "999001": "牛逼"
}
```

保存后**重启插件或触发热重载**即可生效。

### 3.2 全局扩展（环境变量，不随插件分发）

1. 创建任意位置的 JSON，如 `D:\maibot_extra_emojis.json`：
   ```json
   { "999001": "牛逼", "999002": "666" }
   ```
2. 在 MaiBot 启动环境设置：
   ```
   QQ_EMOJI_EXTRA=D:\maibot_extra_emojis.json
   ```
3. 重启 MaiBot。

---

## 4. 效果验证

映射生效后，表情回应通知会显示对应名称（配置 `emoji.optimize_unknown_emoji = false` 时）：

```text
[事件-群消息表情回应] 凯特艾 对消息(ID:-453293849)表达了 [点赞]
```

- 已知表情 → 显示名称（如 `[点赞]`、`[流泪]`）
- 未知表情 + 优化关（默认）→ `[未知表情999999]`
- 未知表情 + 优化开 → `一个表情`

---

## 5. 如何确定未知表情的真实名称（反向建表）

表情回应扩展 ID（如 12951、379、999xxx）无公开映射，只能实测积累：

1. 用 `/el debug s` 对一条消息贴目标表情（`EMOJI_ID` 或改配置）；
2. 在 QQ 客户端查看该表情的显示名；
3. 把 `id → 名称` 加入 `emoji_reaction_extra.json`。

> 建议顺手把测出的新 ID 回报给插件作者，合并进内置扩展表。
